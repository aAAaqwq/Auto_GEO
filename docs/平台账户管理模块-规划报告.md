## 1. 项目背景与目标

### 1.1 项目背景

AutoGeo 是一个 GEO（Generative Engine Optimization）智能内容分发平台，核心功能是自动生成文章并发布到多个内容平台（知乎、百家号、头条号、搜狐号、微信公众号等 **37+ 平台**）。

当前系统已经具备基本的账号 CRUD 和授权功能，但在 **多平台账号管理效率、批量操作体验、授权可靠性** 等方面存在明显不足，需要系统化增强。

### 1.2 核心目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| **多平台登录** | 支持用户在同一界面管理 37+ 个平台的多个账号，每个平台可添加多个账号 | P0 |
| **一键授权** | 通过浏览器自动化（Playwright / AdsPower）实现一键扫码/密码登录授权 | P0 |
| **授权健康监控** | 自动检测账号授权是否过期，提前预警 | P0 |
| **分组标签管理** | 按自定义分组和标签组织账号，支持批量操作 | P1 |
| **批量操作** | 支持批量启用/禁用/删除/移动分组/检测 | P1 |
| **操作审计** | 记录所有账号关键操作，支持回溯 | P2 |
| **数据隔离** | 多用户系统，每个用户只能看到和操作自己的账号 | P0 |

### 4.4 数据流

```
用户操作 → Pinia Action → API 调用 (axios + JWT) → FastAPI 路由
                                                      ↓
                                              SQLAlchemy ORM
                                                      ↓
                                              数据库 (SQLite/PG)
                                                      ↓
                                            响应 → Pinia State → Vue 组件渲染
```

**授权流程数据流**：

```
用户点击"授权" → startAuth API → PlaywrightManager.create_auth_task()
                                      ↓
                              打开浏览器 → 用户扫码/密码登录
                                      ↓
                              confirmAuth API → _finalize_auth()
                                      ↓
                              提取 Cookie + Storage → AES加密 → 入库
                                      ↓
                              WebSocket 通知前端 → 刷新列表
```

虽然 API 已完整，但有几处可以优化：

1. **分页响应解析优化**：`loadAccounts` 中 `data.items` 的解析逻辑需要适配后端 `PaginatedResponse` 格式

## 9. 技术风险与应对

| 风险 | 等级 | 影响 | 应对措施 |
|------|------|------|----------|
| Playwright 浏览器授权失败 | 🔴 高 | 用户无法完成授权 | 增加重试机制 + AdsPower 备选方案 + 手动确认兜底 |
| Cookie 过期过快 | 🟡 中 | 频繁需要重新授权 | 实现自动定期检测 + 过期前预警通知 |
| Windows 下 Playwright 兼容性 | 🟡 中 | 部分环境无法启动浏览器 | 已使用 ProactorEventLoop 修复；提供 CDP 远程连接备选 |
| 前端组件拆分后状态管理复杂 | 🟡 中 | 组件间通信困难 | 统一使用 Pinia Store 管理状态，组件只负责展示 |
| 37+ 平台的适配器维护 | 🟢 低 | 新平台接入成本高 | 统一的 BasePublisher 抽象 + 平台配置化 |
